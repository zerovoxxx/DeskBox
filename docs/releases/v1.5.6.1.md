# DeskBox 1.5.6.1

## Shortcut icon recovery

This local release integrates upstream `main` at `22f231299a64225312864667e6407b166e07a313` and retains the existing logon tray host fix.

The installed 1.5.5.1 process held a generic white document bitmap for Hyper-V even though its stored shortcut metadata pointed at a valid icon. Paradox also had bytes cached from its launcher executable rather than its selected Windows Installer icon. A non-null bitmap stopped item hydration retries, so a transient or incorrect fallback could remain visible for the entire process lifetime. Clearing Explorer's cache did not clear these application caches.

The older loader queried explicit DLL and extensionless icon resources as ordinary Shell files before trying their selected resource index. Upstream already corrected part of that ordering; this release also reads the persisted `.lnk` icon location and signed index before Shell metadata, respects `IconEnvironmentDataBlock`, decodes ICO content regardless of extension, and keeps unresolved shortcut sources out of successful caches. A final bounded retry crosses the Shell's 30-second failure backoff. Extensionless resource cache keys now include the index and resource/shortcut file versions.

The exact reason the first metadata read failed during the earlier logon was not logged. The stale generic bitmap and incorrect resolved source were verified directly in the running process; incomplete metadata and temporarily unavailable resources are covered by regression tests.

## Validation

- 55 focused icon/tray tests passed, including an incomplete cached metadata fixture, resource recovery without modifying the shortcut, extensionless ICO artwork equality, signed indexes, invalid resources and cache invalidation.
- Full suite: 4635 passed; one unchanged Native AOT audit script test was blocked by Microsoft Defender/AMSI. No antivirus bypass or exception was applied.
- The canonical current Debug build started successfully. Live cache bytes decoded to the native Hyper-V and Paradox artwork, and both displayed widget items referenced the corresponding decoded bitmaps.
- Local x64 packaging uses the framework-dependent runtime-download installer profile (`SelfContained=false`, `WindowsAppSDKSelfContained=false`).

A genuine reboot/logon remains a separate acceptance check; a manual startup invocation does not establish that result.

## 原因与修复

白纸图标被当作成功图片缓存后，界面不会继续重试。Hyper-V 的资源 DLL 和 Paradox 的无扩展名 ICO 文件还曾被当作普通文件查询图标，返回了文件类型默认图标。此版本优先读取快捷方式保存的资源位置与索引；解析失败保持可重试，并修复无扩展名 ICO 的解码与缓存键。清理 Windows 图标缓存无法代替这些代码修复。
